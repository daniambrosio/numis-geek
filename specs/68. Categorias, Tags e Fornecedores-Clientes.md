# Spec 68 — Categorias, Tags e Fornecedores/Clientes

Status: 📝 Draft

Primeira spec da trilha **Despesas (Numis)**. Trilha completa: 68 (cadastros) → 69 (cartões/faturas) → 70 (transações) → 71 (import LLM) → 72 (contas a pagar/receber) → 73 (ETL Notion cadastro) → 74 (dashboard despesas) → 75 (meta renda passiva).

## Contexto

O lado "Numis" do sistema (despesas) nunca saiu do protótipo. Antes de qualquer Transaction existir, precisamos dos cadastros que ela referencia: categoria (com hierarquia), tags livres e party (fornecedor/cliente). Decisões da entrevista de 2026-08-09:

- Categoria: CRUD com subcategoria (1 nível) + tags livres por transação.
- Party: **opcional** na transação; auto-criada pelo import a partir da descrição (spec 71); consolidação por merge manual.

## Modelo

### `category`

| coluna | tipo | notas |
|---|---|---|
| id | String(36) uuid PK | |
| workspace_id | FK workspace | scoped |
| name | String(60) | único por (workspace, parent_id) |
| parent_id | FK category, nullable | 1 nível só — parent não pode ter parent (validação de serviço) |
| kind | Enum `EXPENSE \| INCOME \| TRANSFER` | herda do parent quando subcategoria; TRANSFER fica fora de qualquer soma de despesa/receita |
| color | String(7) nullable | hex; subcategoria herda do pai se null |
| is_active | Boolean default true | desativa sem apagar (tx antigas continuam apontando) |
| created_at / updated_at / created_by / updated_by | | padrão do repo |

Seed (migration data op): as 11 do protótipo — Renda (INCOME), Transferência (TRANSFER), e Mercado, Restaurante, Transporte, Casa, Lazer, Saúde, Tecnologia, Tarifas, Viagens (EXPENSE), com as cores do `prototypes/index.html` (`CATEGORIES`).

## Backend

- CRUD REST padrão do repo: `/api/categories`, `/api/tags`, `/api/parties` (list/create/update/deactivate). Workspace-scoped, `role in (admin, sysadmin)` pra escrita, member lê.
- `POST /api/parties/{id}/merge` body `{ source_party_id }` — merge com audit log.
- Validações: categoria com parent não pode virar parent; delete de categoria/party só desativa se referenciada.

## Frontend

- Página `/cadastros` (label sidebar: **Cadastros**, grupo de despesas) com 3 abas: Categorias, Parties, Tags.
  - Categorias: árvore de 2 níveis, cor, kind, criar/editar/desativar inline.
  - Parties: lista com busca, badge kind, contagem de aliases; ação Merge (seleciona 2 → escolhe sobrevivente).
  - Tags: lista simples, rename, delete se sem uso.
- Modais fecham com ESC (`useEscapeKey`). Ações async com disabled+spinner, erros em toast.
