# Spec 63 — Prototype parity sweep

## Status: 📝 Draft

## Motivação

O audit de coerência de 2026-07-28 (spec-implementation-auditor) mapeou 13 divergências
entre `prototypes/index.html` e a implementação React atual. O repositório tem regra
dura (memory `follow_prototype_strictly`) de reproduzir estrutura/ordem do protótipo,
mas várias telas acumularam desvios ao longo das entregas incrementais.

Esta spec **não redesenha nada** — apenas reconcilia o React com o protótipo,
tela por tela, para restaurar a paridade prometida.

Escopo cobre: Dashboard, Portfolio, Snapshots, SnapshotDetail (parcial),
AssetDetail, Assets, Distributions, AssetMovements, Audit.

## Priorização por criticidade

**Alta** (perda de informação para o usuário / bloco crítico do fluxo):

   "Resolver pendências"/"Reprocessar APIs" e card "Próximo fechamento" (proto 7143–7229).

   fechamento + Δ MoM + Proventos do mês + SnapshotChart (proto 7231–7264).

   + legenda colorida + CLI tip card (proto 7286–7363).

5. **DIS-yoc** — coluna `YoC` na vista "Por ativo" de Distributions (proto 5340).

**Média** (UX degradada mas contornável):

   proto = "Patrimônio total" + Investimentos/Caixa/Cartões; React = "Patrimônio

## Estratégia de entrega

Cada item vira uma commit-unit isolada (branch/PR próprio se necessário). Testes
`.test.tsx` para os componentes tocados quando aplicável (memory
`jsdom_misses_backend_shape` diz que jsdom não pega alguns bugs — playwright headless
opcional para modais afetados).

Ordem sugerida:
- Sprint 1 (Alta): SNP-hero → SNP-evolution → SNP-cols → AD-notes → DIS-yoc.
- Sprint 2 (Média): DBH-trends → HERO-pills (após decisão de escopo) → AST-* → DIS-attachments → AM-daterange.
- Sprint 3 (Baixa): AUD-filters → PORT-top10-subheader.
