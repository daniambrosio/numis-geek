# Spec 74 — Dashboard de Despesas e despesa mensal média

## Status: 📝 Draft

Trilha Despesas (ordem de implementação): 68 → 69 → 70 → 72 → 73 → 71 → **74** → 75. Depende da 70 (transactions) com dados reais importados via 71.

## Contexto

**A métrica-alvo de toda a trilha**: quanto é a despesa mensal média do user. Decisão da entrevista (2026-08-09):

> Média dos **últimos 12 meses fechados**, excluindo transferências e renda.

## Definição precisa da métrica

Uma tx conta como **despesa** quando passa por TODOS os filtros, nesta ordem:

1. **Exclusões estruturais** (independem de categoria — fecham o buraco do import sem categoria):
   - `paid_invoice_id IS NOT NULL` → é pagamento de fatura, nunca despesa;
   - `transfer_group_id IS NOT NULL` → é perna de transferência entre contas próprias;
2. `amount < 0`;
3. subcategoria com `kind = EXPENSE` (decisão 2026-08-09 v2: kind mora na SUB; raiz é agrupador e nunca é referenciada por tx), **ou sem categoria** — tx negativa sem categoria conta como despesa (não deixar buraco silencioso), e o dashboard mostra o % sem categoria como alerta de qualidade. `kind = TRANSFER` e `kind = INCOME` ficam fora. Agrupamento por "categoria" nos relatórios = agrupar pelas raízes (os agrupadores), somando as subs — raiz mista mostra despesa e renda separadas.

Demais regras:

- Card tx conta no **event_date da parcela** (cada parcela no seu mês — coerente com a decisão de parcelamento da spec 70). Parcelas com event_date futuro caem em meses futuros e, como a média usa só meses fechados, nunca a poluem.
- Moeda: soma em `amount_brl`; toggle BRL/USD no hero (padrão dual-currency do repo, spec 41).
- "12 meses fechados" = do 1º dia de `mês_atual - 12` até o último dia de `mês_atual - 1`. Mês corrente fica fora da média (parcial), mas aparece no dashboard como "mês em andamento".
- **Nota de reconciliação**: o `/api/transactions/summary` (spec 70) é fluxo bruto — inclui transferências e pagamentos de fatura; os números de "Saídas" das duas telas divergem **por definição**. Documentar no tooltip do hero.

## API

`GET /api/expenses/summary` →

```json
{
  "avg_monthly_expense_12m": …, "avg_monthly_income_12m": …,
  "months": [ { "ym": "2026-07", "expense": …, "income": …, "net": …,
                "by_category": [ {"category_id", "name", "color", "total"} ],
                "uncategorized_pct": … } ],   // 13 entradas: 12 fechados + corrente
  "top_categories_12m": […], "top_parties_12m": […]
}
```

Tudo em BRL e USD (mesmo shape `_brl`/`_usd` das telas dual-currency).

## Frontend — página `/expenses` (label sidebar: **Despesas**; redirect PT `/despesas`)

1. **Hero**: Despesa mensal média (12m) — o número canônico — + receita média e resultado médio; toggle BRL/USD; tooltip explicando as exclusões.
2. **Gráfico de barras mensal** (13 meses: 12 fechados + corrente destacado como parcial): despesa por mês, linha da média. Usar o padrão de chart do repo (ProventosChart).
3. **Tabela categoria × mês**: linhas = categorias top-N + "Outros", colunas = últimos 6/12 meses, célula com valor; coluna final média.
4. **Top parties 12m** — card lateral.
5. Badge de qualidade: "X% sem categoria" com link filtrado pra Movimentações.

### Deltas declarados vs protótipo

- **`/expenses` é tela nova sem par no protótipo** — design novo declarado, no padrão visual das demais páginas. A `OrcamentoPage` do proto (l.6522-6728) é **metas-cêntrica** (coluna "Meta · mês", HBars vs target, status estourado) e permanece dona do item "Orçamento" → `/budget` da sidebar, que será entregue por spec futura de metas (feature 13). A tabela categoria × mês desta spec é *inspirada* na grade da OrcamentoPage, não fiel a ela.
