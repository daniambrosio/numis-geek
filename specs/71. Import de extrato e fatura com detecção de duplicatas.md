# Spec 71 — Import de extrato e fatura com detecção de duplicatas

Status: 📝 Draft

Trilha Despesas: 68 → 69 → 70 → **71** → 72 → 73 → 74 → 75. Depende da 70 (transaction) e 69 (invoice). É a **entrada principal de dados** do lado Numis: o user não digita transação — importa arquivo.

## Contexto

Decisões da entrevista (2026-08-09):

- Formatos reais do user: **OFX, PDF (fatura), CSV/XLSX (Wise/Nubank), screenshot**.
- **LLM pra tudo** — reusa o pipeline `ExtractionJob` (specs 38/48/49/58): attachment → job → extracted_json → review UI → apply. Sem parser determinístico por ora (otimização futura se algum formato ficar frequente).
- **Sem histórico do Notion** — o histórico entra por estes arquivos originais das instituições.
- **Dedup em 3 camadas obrigatório desde o dia 1**: os arquivos do user têm períodos sobrepostos.
- Party auto-criada da descrição (match exato via alias; consolidação manual depois — spec 68).

## Dedup — 3 camadas

1. **Hash do arquivo**: `attachment.content_hash` (SHA-256, coluna nova via batch_alter). Upload de arquivo com hash já existente no workspace → recusado na hora com mensagem apontando o attachment original.
2. **Fingerprint natural da tx**: `transaction.import_fingerprint` = sha1 de `(source_id, event_date, amount, currency, description_normalized)` — coluna indexada, nullable (tx manual não tem). No apply, linha extraída cujo fingerprint já existe na mesma conta/cartão → bucket "duplicada" (default: skip, mostrada no review).
3. **Aviso de overlap de período**: `extraction_job` ganha `statement_period_start/end` (o LLM extrai do documento). Se a faixa intersecta a de um job CONFIRMED anterior da mesma conta/cartão → banner "Overlap com import de DD/MM–DD/MM — N linhas caíram como duplicatas" antes do apply.

Caso legítimo de tx idêntica no mesmo dia (2 cafés de R$ 5): aparece no bucket duplicada e o user pode promover a linha pra "importar mesmo assim" (força fingerprint com sufixo `:2`).

## Extensões ao pipeline ExtractionJob

- Novos `ExtractionSourceHint`: `BANK_STATEMENT`, `CARD_INVOICE`.
- `extraction_job` ganha `checking_account_id?` / `credit_card_id?` (scoping, análogo ao `institution_id` da spec 58) + `statement_period_start/end`. Jobs desse fluxo não têm snapshot_id.
- Templates de prompt novos em `extraction_templates`:
  - `BANK_STATEMENT`: emite `transactions[] { event_date, description, amount signed, currency, balance_after? }` + `period {start,end}`.
  - `CARD_INVOICE`: emite o de cima + `invoice { close_date, due_date, total, iof_total? }` + por linha `installment "5/12"?`, `fx { usd_amount, rate }?` (compra internacional).
- Classify (novo serviço `_classify_bank_import`):
  - resolve party por `party_alias` (match exato normalizado); sem match → marca "party nova: UBER *TRIP" (criada no apply).
  - calcula fingerprint e bucketiza: **novas / duplicadas / pagamento de fatura detectado** (linha de extrato que bate com invoice CLOSED não paga: mesmo valor ±1%, data entre close e due+10 → sugere link `paid_invoice_id`).
  - CARD_INVOICE: resolve/cria a `invoice` pelas datas do documento; seta `total_amount` e `status=CLOSED`; linha `X/Y` de parcela vira tx com installment preenchido (o vínculo parent entre parcelas de meses diferentes é best-effort por descrição+valor).
- Apply: cria transactions com `is_reconciled=true`, `import_fingerprint`, parties novas + aliases; atômico; auditado.

## UX

- Botão **Importar extrato** na página da conta checking e **Importar fatura** no `/cartao/:id` (destrava os botões disabled da spec 69). Upload → job async (padrão spec 48: polling, spinner, toast).
- Review modal (padrão `BulkIncomeReviewModal`): tabela com buckets colapsáveis (novas / duplicadas / pagamento de fatura), edição inline de categoria/party antes do apply, contador "Importar N transações". ESC fecha.
- Timeout: LLM pode levar 1–3 min (proxy já configurado pra 600 s).

## Fora de escopo

- Reconciliação com contas a pagar/receber — a spec 72 pluga um hook aqui.
- Auto-categorização por LLM (o modelo pode sugerir `category_hint`; aplicar de verdade é spec futura).
- Parser determinístico por formato.

## Deliverables

2. Templates LLM + `_classify_bank_import` + apply + testes pytest (dedup nas 3 camadas, overlap warning, pagamento de fatura detectado, party nova com alias, re-upload do mesmo arquivo recusado).
3. UX de upload + review modal + testes de componente.
