# Spec 72 — Contas a Pagar e a Receber

Status: 📝 Draft

Trilha Despesas: 68 → 69 → 70 → 71 → **72** → 73 → 74 → 75. Depende de 68 (party/category), 70 (transaction) e 71 (hook de reconciliação no import).

## Contexto

Obrigações/direitos **futuros** (aluguel dia 5, salário dia 10, boleto avulso), distintos de Transaction (passada e realizada). Decisões da entrevista (2026-08-09):

- Tabela única `scheduled_transaction` com `direction: PAYABLE | RECEIVABLE` — mesmo padrão de discriminador da transaction.
- Frequências: **one-off, mensal fixo, anual, parcelamento fixo (N ocorrências)**.
- Vira Transaction **pela reconciliação automática no import de extrato** (spec 71), com fallback manual (marcar pago / adiar / cancelar quando em atraso).

### Materialização

Job APScheduler diário (`scheduler.py`, padrão dos jobs existentes): pra cada rule ativa, garante occurrences PENDING até `today + 90 dias`. Idempotente. Criar/editar rule dispara materialização imediata; editar rule só afeta occurrences futuras ainda PENDING.

## Reconciliação (hook na spec 71)

No `_classify_bank_import`, cada linha nova tenta casar com occurrence PENDING da mesma direção (sinal do amount):

- **valor** dentro de ±5%, **data** dentro de ±5 dias do due_date, e (party via alias **ou** descrição normalizada contém a description da occurrence).
- Match → linha ganha sugestão "quita: Aluguel · vence 05/08" no review; confirmada no apply → occurrence PAID + `paid_by_transaction_id` + tx herda category/party da occurrence se vazios.
- 2+ candidatos → sugere o de data mais próxima, dropdown pra trocar (lição do matcher: tie-breaker de data).

Fallback manual na página: occurrence PENDING com `due_date < today` vira **Em atraso** (badge âmbar); ações: **Marcar pago** (pede data + opcional link a uma tx existente não-reconciliada; sem tx → PAID sem link, com aviso), **Adiar** (muda due_date), **Cancelar**.

## API + Frontend

- CRUD `/api/recurrence-rules` e `/api/scheduled-transactions` (+ ações pay/postpone/cancel). `GET /api/scheduled-transactions/forecast?months=3` — fluxo futuro agregado por mês (a pagar, a receber, líquido).
- Página `/contas` (label: **Contas a Pagar/Receber**): KPIs do mês (a pagar, a receber, líquido, em atraso); lista de próximos vencimentos agrupada por mês com badge de status; aba/painel de Recorrências (CRUD das rules); composer entry "Conta a pagar/receber". Modais com ESC, async com spinner+toast.
