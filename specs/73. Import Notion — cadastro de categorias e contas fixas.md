# Spec 73 — Import Notion: cadastro de categorias e contas fixas

Status: 📝 Draft

Trilha Despesas: 68 → 69 → 70 → 71 → 72 → **73** → 74 → 75. Depende de 68 (category) e 72 (recurrence_rule). Utility, não produto — padrão das specs 07a/07c.

## Contexto

Decisão da entrevista (2026-08-09): **zero histórico transacional do Notion** (o histórico entra pelos arquivos originais das instituições, spec 71). Do Notion Numis só vale o **cadastro curado**:

1. **Categorias** (com a hierarquia real do user) — substituem/complementam o seed genérico das 11 do protótipo.
2. **Contas fixas mensais** (mapa de contas a pagar/receber recorrentes: aluguel, planos, streamings, salário/consultorias) → viram `recurrence_rule` + occurrences materializadas.

Fornecedores/clientes que aparecerem nessas bases entram como `party` de carona.

## Padrão (igual 07a/07c)

- Fetch live via Notion MCP na sessão, com as lições registradas: criar view **sem filtro** + múltiplos sorts; paginação completa; nunca confiar em views com filtro.
- Snapshot intermediário `data/notion_numis_cadastro_export.json` (gitignored) — reexecutável sem re-hit no Notion.
- Script CLI `--dry-run` (default, mostra plano) / `--apply` idempotente contra o DB local. Antes do apply em produção: backup do dia (regra dura do repo).
- Entrevista curta na execução: o agente pergunta o mapeamento quando uma categoria do Notion não tiver equivalente óbvio (merge com seed das 11? criar nova? qual kind?).

## Mapeamentos (a confirmar na execução, quando abrirmos as DBs reais do Notion)

| Notion | Numis-Geek |
|---|---|
| DB de categorias (nome/grupo) | `category` (name, parent via grupo, kind inferido) |
| DB contas fixas: nome, valor, dia, frequência | `recurrence_rule` (direction por sinal/tipo, MONTHLY/YEARLY, day_of_month, amount) |
| Fornecedor/cliente citado | `party` + `party_alias` |

Idempotência: chave natural por nome normalizado; re-run atualiza em vez de duplicar.

## Deliverables

1. `scripts/import_notion_numis_cadastro.py` com dry-run/apply + JSON snapshot.
2. Execução assistida com o user (as DBs do Notion Numis precisam ser abertas juntas pra fechar o mapeamento real — os nomes acima são chute educado).
3. Testes pytest do transform JSON→modelo (com fixture de JSON real anonimizado) — o fetch MCP em si não é testável offline.
