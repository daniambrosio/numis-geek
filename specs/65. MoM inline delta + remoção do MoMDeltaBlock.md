# Spec 65 — MoM inline delta em Posições Congeladas + remoção do MoMDeltaBlock

## Status: 🚧 In Progress (~60%: frontend entregue em 25c7bfd/93c80d2; pendente a limpeza backend do SUSPICIOUS_DELTA — enum, detect_suspicious_deltas, endpoints e testes ainda vivos)

## Contexto

Spec 62 (SUSPICIOUS_DELTA + MoMDeltaBlock) produziu muitos falsos-positivos e virou obstáculo em fechamentos reais:

- Value-mode assets sem movement registrado disparam anomalia (Meli Dólar, Fundo Segurança, saldos em conta)
- Snapshots antigos com valores herdados de versões diferentes do detector
- Edits manuais que não geram pendency correspondente
- UX confusa: botão "Confirmar" trava, comparação com baseline errado (Mai/26 quando Jun/26 está IN_REVIEW), mensagem "bloqueia o fechamento" enganosa
- 4 rounds de bugfix em 1 dia (dark-mode, JSON cru, delta_pct sem sinal, botão travado, non-blocking) e ainda tinha issue

Feedback direto do user (2026-08-01): "essa parada de anomalias esta so atrapalhando... isso foi desenvolvido pela metade?"

Substituir por **delta inline** na tabela de Posições Congeladas — informação contextual onde o user já está olhando, sem bloco separado, sem pendency, sem confirm.

### Backend — expor prev_mv_native no items endpoint

`SnapshotItemOut` ganha campo `previous_mv_native: Decimal | None`:
- Backend `GET /snapshots/{id}/items` popula com o valor do item do **mês calendário anterior** (não CLOSED — só mês-1 calendário)
- Se prev snapshot não existe → None
- Se prev existe mas asset não tem item lá → None (novo asset)

Exemplo: Julho consulta Junho independente de status.

   - Se prev 0 → `—` (evita div/0)
   - Sem ícone, sem badge, sem threshold — só cor

## Trade-offs conhecidos

- **Perde detecção proativa** de anomalias: user precisa notar visualmente na tabela. Aceito — falsos-positivos superavam sinal real.
- **Se um bug futuro criar valores absurdos** (ex.: aquele Meli Dólar R$ 5.452 em vez de R$ 281), user vê o Δ% vermelho gigante e investiga — mesmo output, sem ceremony.
