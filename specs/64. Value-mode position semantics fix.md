# Spec 64 — Value-mode position semantics fix

## Status: ✅ Done

Nota: `_effective_item_quantity` em `snapshot.py` é da Fase 3.1 (trabalho anterior), NÃO é o fix desta spec — evitar confusão ao auditar.

## Contexto

`compute_position` (services/positions.py:253) marca movements value-mode com `is_non_cotado_row = r.quantity is None`. Mas memory [[modo_valor_qty_1_invariant]] estabelece que movements value-mode SEMPRE têm `quantity=1` (não NULL). Consequência:

1. BUY qty=1 gross=X → cai no path COTADO, popula `basis_qty=1`, `basis_cost_brl=X`
2. SELL qty=1 gross=Y → cai no path COTADO, `running_qty = 1-1 = 0`
3. Linha 284: `if SELL and abs(running_qty) < _TOLERANCE: reset_cotado_basis()` — limpa `basis_qty` e `basis_cost_brl`
4. `total_invested_brl = 0` + `asset_has_position() → False`
5. Snapshot service pula o asset silenciosamente. Item some do fechamento.

**Caso concreto (2026-08-01):** LFT mar/2028 XP com BUY R$ 4.838 (2025-05-06) + SELL R$ 522 (2025-09-25, resgate parcial) sumiu de Jul/26. User teve que adicionar manualmente com o valor do extrato (R$ 5.278,74). Confirmado pelo user: "a venda que fiz nao zerou o produto. Foi só uma venda de uma parte do saldo. Isso é o problema de origem".

Sistema precisa distinguir:
- **Value-mode SELL** = redução de saldo em BRL (`non_cotado_basis_brl -= gross`)
- **Cotado SELL** = venda de N unidades (`running_qty -= qty`; se zerar, `reset_cotado_basis`)

## Fix técnico

### positions.py (`compute_position`)

Alterar a checagem `is_non_cotado_row`:

```python
# Passar asset pro helper (mudança de assinatura interna)
asset = db.get(Asset, asset_id)  # já é chamado no início
is_value_mode_asset = (
    asset.asset_class is not None
    and asset.asset_class not in _COTADO_CLASSES
)

# Dentro do loop:
is_non_cotado_row = r.gross_amount is not None and (
    r.quantity is None or is_value_mode_asset
)
```

Regras subsequentes se mantêm:
- BUY value-mode: `non_cotado_basis_brl += gross * effective_fx`
- SELL value-mode: `non_cotado_basis_brl -= gross * effective_fx`
- Cotado (STOCK/ETF/REIT/CRYPTO/OPTION): comportamento inalterado

### `reset_cotado_basis` guard

O trigger `if SELL and abs(running_qty) < _TOLERANCE: reset_cotado_basis()` só faz sentido pra assets cotados. Adicionar guard:

```python
if r.type == AssetMovementType.SELL and abs(running_qty) < _TOLERANCE:
    if not is_value_mode_asset:
        running_qty = Decimal("0")
        reset_cotado_basis()
```

Value-mode com running_qty=0 é o estado normal (qty é convenção fixa). Não deve trigger reset.

### Invested negativo — fica para spec própria

`Tesouro Selic 2029`, `FGTS - Carrefour`, `FGTS - Meli` e `Saldo em Conta (Wise)` terminam
com `total_invested_brl` negativo. Não é regressão do fix (Carrefour e 2029 já eram
negativos antes): em modo valor o SELL subtrai o gross do resgate, que carrega
rendimento acumulado além do principal, e parte do histórico de aportes nunca entrou
no sistema (base começa no import do Notion). Semântica "invested = Σ aportes − Σ resgates"
precisa de decisão própria.
